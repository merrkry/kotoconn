# Drive TUN TCP connections in their owning worker

A TUN endpoint runs one worker per queue, with independent receive/dispatch and transmit futures. A stable flow hash assigns each TCP connection or UDP association to one worker. Packets arriving elsewhere are forwarded to their owner. Queue membership stays fixed until the inbound stops. On Linux, replies teach TUN which queue owns a flow and reduce subsequent forwarding.

Each Linux worker owns a Tokio runtime with one worker thread. It creates the async TUN device and polls native sockets there so readiness and forwarding share an I/O driver. Shutdown joins workers before releasing runtimes; abort cancels their tasks and shuts down the runtimes without blocking the caller.

Policy runs on the shared QuickJS thread before native handoff. Future sniffing belongs before outbound selection; buffered prefixes must preserve order and receive credit. Device creation stays separate from packet and stream contracts. The generic packet entry point uses the caller's runtime to support other platform adapters and deterministic protocol tests.

The worker owns each TCP state machine and drives it directly through our smoltcp fork. It passes validated IP/TCP representations to the connection and encodes output into worker-owned packet storage. Per-connection virtual devices, interfaces, route tables, socket sets, packet queues and driver tasks are unnecessary. Ready notifications are deduplicated per connection; ordered deadlines select timer work without scanning all connections. Bounded turns preserve fairness. A blocked output records the connection for retry instead of suspending shared reception.

Application tasks receive a Stream that exchanges immutable payload blocks with the worker. RX blocks become readable after TCP establishes a contiguous prefix. TX blocks remain available for retransmission until ACK. The socket is never shared with application tasks, and no second byte buffer or bridge task sits between TCP storage and Stream. The fork supplies storage and host-context interfaces; Tokio, allocation policy, pools and worker scheduling remain in Kotoconn. This replaces the earlier design of fixed smoltcp rings and external byte queues because it duplicated storage, copying, packet parsing and scheduling.

The offset-zero IP fragment binds its datagram to the transport flow's worker. Fragments received earlier wait as owned receive chunks; establishing the binding also takes those chunks for delivery to that worker. Subsequent fragments follow the binding. Reassembly therefore runs beside the connection state instead of forwarding fragments to an unrelated worker and sending the completed datagram back. Pending chunks move without copying payloads; the existing contiguous IP reassembly buffer remains.

The shared routing table is sharded by the fragment key. IPv4 keys contain source, destination, protocol and ID; IPv6 keys contain source, destination and ID. Including the protocol in the IPv6 key would separate conflicting fragments that must poison the same assembly. A binding stays fixed until completion, eviction or expiry, and queued fragments retain its identity so they cannot enter a later use of the same ID. Pending chunks, their backing allocation sizes, routing entries and incomplete assemblies share the reassembly allowance. Expiry starts with the earliest received fragment, including an orphan, and the endpoint expires routing entries even without new traffic. Poisoned assemblies retain their original deadline.

Budget exhaustion wakes every worker to reclaim old orphan batches and incomplete assemblies in bounded turns. Eviction retires the binding so stale queued fragments cannot enter a reused ID. Poisoned identities keep their original expiry. Traffic can recover from fragment loss without waiting for reassembly expiry.

Stopping admission ends UDP associations while established TCP connections drain. Each worker reports completion only after observing stopped admission and removing every TCP connection. Scope guards track worker-owned connection work without spawning placeholder tasks. The supervisor then drains transmit queues before releasing the device. Forced cancellation interrupts blocked I/O. A failed worker or aborted endpoint cancels that inbound's connections without cancelling other inbounds.
